## Bounded implementation

One shared `projectUserDecision` recognizer now feeds deterministic VCC extraction and source-addressed observer serialization. It requires both a supported tool name and a recognized result shape. The projection carries only confirmed answer lines and a bounded status annotation for recognized cancellation/error/timeout/control outcomes; raw result text remains source-addressed, but the observer prompt says not to promote answer-shaped text when such a status annotation is present. Observer output does not receive arbitrary details, previews, option descriptions, or synthetic source ids.

The existing `ask_user_question` structured and `User answers:` text paths, clipping, eight-line cap, and source references remain. The rpiv text fallback is exact-prefix and rejects ambiguous quoted pairs. No answer is inferred from tool arguments or offered/recommended options. Empty multi-select is represented only for OMP's explicit non-timeout `multi:true` result. Unknown shapes are skipped. Notes are separately labeled; eko option-note keys remain explicit option values because the result omits option labels. Supi's `needs_discussion` status accompanies any answered items.

`src/core/normalize.ts` now carries `details` only for the supported exact names (`ask_user_question`, `ask_user`, `ask`). The deterministic path is `src/extract/user-decisions.ts` through VCC section building. The OM path is `src/om/serialize.ts`, which projects recognized fields into text under the original source entry. No call/result correlation or proximity matching was added because recognized details and the accepted rpiv envelope provide question identity.

The test suite includes confirmed explicit `No`, batch skipped items, combined/custom answers, selected and unselected comments, form qualification, OMP confirmed select-none versus timeout default, rpiv ambiguous text, cancellation/error/control/unknown guards, and matching VCC/observer projection with source ids.

## Limits

These are best-effort adapters for the pinned source shapes, not a universal tool contract. Host serialization may change, and OMP is a separate coding-agent fork rather than a Pi extension. All observed behavior above is static source inspection; Blackhole tests use hand-authored fixtures and do not prove third-party runtime correctness.
